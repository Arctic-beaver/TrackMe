# Tiempio — приёмочные сценарии MVP

**Статус:** базовый контракт  
**Этап:** 0  
**Формат:** Given / When / Then

## 1. Назначение

Сценарии описывают наблюдаемое поведение продукта. Они не требуют конкретного
тестового фреймворка, но каждый сценарий должен стать автоматизированным тестом
или явно отмеченной ручной release-проверкой соответствующей фазы.

## 2. Первый запуск и сохранность

### 2.1. Чистый запуск

**Given** Tiempio запускается впервые  
**When** приложение завершает инициализацию  
**Then** открывается пустая доска Today  
**And** пользователь не видит технических диалогов базы или файловой системы  
**And** локальная база создаётся в application data.

### 2.2. Перезапуск

**Given** пользователь создал задачи, проекты и теги  
**When** он штатно закрывает и снова открывает Tiempio  
**Then** все данные и настройки восстанавливаются без ручного импорта  
**And** стартовым экраном остаётся Today.

### 2.3. Отсутствие сети

**Given** компьютер не подключён к интернету  
**When** пользователь запускает и использует основной MVP-функционал  
**Then** задачи, проекты, календари, темы и фильтры продолжают работать.

## 3. Создание и редактирование задачи

### 3.1. Значения по умолчанию

**Given** пользователь открыл создание задачи  
**When** форма показана впервые  
**Then** статус равен `TODO`  
**And** оценка равна одному дню  
**And** повторение выключено  
**And** старт находится в автоматическом режиме.

### 3.2. Обязательные поля

**Given** название или дедлайн не заполнены  
**When** пользователь нажимает «Сохранить»  
**Then** задача не создаётся  
**And** форма указывает конкретное отсутствующее поле  
**And** уже введённые значения не теряются.

### 3.3. Автоматический старт

**Given** оценка равна трём дням, дедлайн — 25 июля  
**When** задача сохраняется с автоматическим стартом  
**Then** желательный старт равен 23 июля  
**And** календарная полоса занимает 23, 24 и 25 июля.

### 3.4. Пересчёт автоматического старта

**Given** задача использует автоматический старт  
**When** пользователь меняет оценку или дедлайн  
**Then** старт пересчитывается по актуальным значениям.

### 3.5. Ручной старт

**Given** пользователь включил ручной старт  
**When** он меняет оценку или дедлайн  
**Then** выбранный старт не переписывается автоматически  
**And** старт позже дедлайна не сохраняется.

### 3.6. Закрытие без сохранения

**Given** пользователь изменил поля открытой задачи  
**When** он закрывает панель и подтверждает отказ от несохранённых изменений  
**Then** исходная задача остаётся без изменений  
**And** пользователь возвращается к прежнему экрану, периоду и фильтрам.

## 4. Доска Today

### 4.1. Четыре статуса

**Given** есть задачи во всех четырёх статусах  
**When** открывается Today  
**Then** каждая задача находится ровно в одной колонке  
**And** дата задачи не исключает её из соответствующей колонки.

### 4.2. Порядок категорий

**Given** в одной колонке есть задача на сегодня, просроченная, рискованная и
будущая задача  
**When** колонка отображается  
**Then** задача на сегодня находится выше просроченной  
**And** просроченная находится выше рискованной  
**And** рискованная находится выше будущей.

### 4.3. Зона риска

**Given** задача оценена в три дня, а дедлайн наступает завтра  
**When** рассчитывается срочность  
**Then** задача относится к `at_risk`.

### 4.4. Просрочка

**Given** дедлайн незавершённой задачи был вчера  
**When** открывается Today  
**Then** задача относится к `overdue`  
**And** имеет красный текстовый или графический индикатор  
**And** смысл не передаётся только цветом.

### 4.5. Перенос Plan for today

**Given** задача была помещена в `Plan for today` вчера и не завершена  
**When** приложение открывается сегодня  
**Then** задача остаётся в `Plan for today`  
**And** получает отметку «перенесено со вчера»  
**And** Tiempio не возвращает её в `TODO` автоматически.

### 4.6. Завершение

**Given** активная задача  
**When** пользователь переводит её в `Done`  
**Then** записывается время завершения  
**And** задача появляется в `Done`  
**And** прогресс связанного проекта обновляется.

### 4.7. Повторное открытие

**Given** выполненная задача  
**When** пользователь возвращает её в незавершённый статус  
**Then** время завершения очищается  
**And** прогресс проекта пересчитывается.

### 4.8. Старые выполненные

**Given** в `Done` есть задачи старше семи дней  
**When** открывается Today  
**Then** они свёрнуты за действием «Показать все»  
**And** последние выполненные задачи отсортированы от новых к старым.

### 4.9. Доступная смена статуса

**Given** drag-and-drop недоступен или пользователь работает с клавиатуры  
**When** открыта карточка задачи  
**Then** статус можно изменить обычным доступным контролом.

## 5. Фильтры

### 5.1. Проект

**Given** выбран проект `Yinkie`  
**When** пользователь просматривает Today, Week или Month  
**Then** видны только задачи и события этого проекта.

### 5.2. Тег

**Given** выбран тег `Работа`  
**When** применяется фильтр  
**Then** видны задачи и серии, связанные с этим тегом  
**And** сущности без тега скрыты.

### 5.3. Сохранение контекста

**Given** пользователь установил фильтр в Today  
**When** он переходит в Week, затем в Month  
**Then** тот же фильтр остаётся активным  
**And** его можно явно сбросить.

## 6. Week и Month

### 6.1. Непрерывная полоса

**Given** задача начинается 23 июля и заканчивается 25 июля  
**When** она показана в Week  
**Then** это одна непрерывная полоса через три дня  
**And** название отображается один раз без создания трёх задач.

### 6.2. Граница недели

**Given** задача проходит через воскресенье и понедельник  
**When** она показана в Month  
**Then** визуальное продолжение на новой строке сохраняет идентичность задачи  
**And** обе части открывают одну карточку.

### 6.3. Время события

**Given** событие назначено на четверг, 15:00  
**When** открывается содержащая его неделя  
**Then** рядом с названием видно `15:00`.

### 6.4. Возврат из карточки

**Given** пользователь открыл задачу из определённой недели или месяца  
**When** он закрывает карточку  
**Then** сохраняются период, фильтры и положение исходного представления.

## 7. Проекты

### 7.1. Создание

**Given** пользователь создаёт проект  
**When** он указывает название и описание  
**Then** проект появляется в списке  
**And** описание может содержать отображаемые безопасные ссылки.

### 7.2. Одна задача — один проект

**Given** задача уже связана с проектом  
**When** пользователь выбирает другой проект  
**Then** старая связь заменяется новой  
**And** задача не дублируется.

### 7.3. Прогресс

**Given** в проекте десять активных конечных задач, три из них выполнены  
**When** открываются Projects или страница проекта  
**Then** показывается `3 из 10` и `30%`.

### 7.4. Только регулярные события

**Given** в проекте нет конечных задач, но есть два повторяющихся события  
**When** открывается список проектов  
**Then** процент не показывается как `0%`  
**And** интерфейс сообщает «2 регулярных события».

### 7.5. Архивация

**Given** проект содержит задачи  
**When** пользователь архивирует проект  
**Then** проект исчезает из списка активных  
**And** его задачи не удаляются и не архивируются автоматически.

## 8. Теги

### 8.1. Пользовательский тег

**Given** пользователь вводит новое название тега  
**When** задача сохраняется  
**Then** тег создаётся и связывается с задачей.

### 8.2. Защита от дублей

**Given** уже существует тег `Работа`  
**When** пользователь вводит `работа` или другое регистровое представление  
**Then** используется существующий нормализованный тег.

### 8.3. Удаление связи

**Given** задача имеет тег  
**When** пользователь удаляет тег из задачи  
**Then** удаляется только связь  
**And** задача и сам тег не исчезают без отдельного действия.

## 9. Повторяющиеся события

### 9.1. Несколько расписаний

**Given** серия «Вокал» содержит вторник 18:00 и четверг 15:00  
**When** открывается неделя с обоими днями  
**Then** показаны два экземпляра одной серии с разным временем.

### 9.2. Экземпляр сегодня

**Given** сегодня соответствует слоту активной серии  
**When** открывается Today  
**Then** экземпляр показывается в `Plan for today`  
**And** проект и теги наследуются от серии.

### 9.3. Завершение экземпляра

**Given** сегодняшний экземпляр регулярного события  
**When** пользователь помечает его выполненным  
**Then** сохраняется состояние только этого экземпляра  
**And** будущие экземпляры серии остаются активными.

### 9.4. Пропуск

**Given** отдельный экземпляр серии  
**When** пользователь выбирает «Пропустить»  
**Then** этот экземпляр больше не требует действия  
**And** серия продолжает создавать будущие экземпляры.

### 9.5. Перенос

**Given** занятие назначено на четверг  
**When** пользователь переносит только его на пятницу  
**Then** исходный экземпляр сохраняет идентичность  
**And** остальные четверги не меняются.

### 9.6. Нет вечной просрочки

**Given** вчера было регулярное событие, с которым пользователь не
взаимодействовал  
**When** наступил новый день  
**Then** вчерашний виртуальный экземпляр не появляется как просроченная конечная
задача.

### 9.7. Изменение серии

**Given** у серии есть завершённые и будущие экземпляры  
**When** пользователь изменяет расписание серии  
**Then** завершённая история не переписывается  
**And** новое правило применяется к будущим виртуальным экземплярам.

## 10. Архивация

### 10.1. Задача

**Given** активная задача  
**When** пользователь архивирует её  
**Then** она исчезает из Today, Week и Month  
**And** остаётся восстановимой.

### 10.2. Серия

**Given** активная повторяющаяся серия  
**When** пользователь архивирует её  
**Then** будущие виртуальные экземпляры больше не показываются  
**And** завершённая история сохраняется.

## 11. Резервная копия

### 11.1. Создание

**Given** в Tiempio есть данные и настройки  
**When** пользователь выбирает «Создать резервную копию»  
**Then** создаётся один файл `.tiempio`  
**And** приложение сообщает об успехе только после проверки снимка.

### 11.2. Восстановление

**Given** после backup пользователь изменил данные  
**When** он восстанавливает проверенный backup и подтверждает замену  
**Then** данные и настройки соответствуют состоянию снимка  
**And** изменения после снимка отсутствуют  
**And** страховочная копия заменённой базы сохранена.

### 11.3. Повреждённый файл

**Given** выбран повреждённый или посторонний файл  
**When** запускается восстановление  
**Then** файл отклоняется до замены текущей базы  
**And** текущие данные продолжают открываться.

### 11.4. Более новая версия

**Given** backup создан более новой несовместимой версией Tiempio  
**When** старая версия пытается его восстановить  
**Then** восстановление блокируется с понятным сообщением  
**And** текущая база не изменяется.

## 12. Напоминания

### 12.1. Дедлайн

**Given** для задачи включено напоминание в день дедлайна  
**When** наступает выбранное локальное время  
**Then** Tiempio показывает системное уведомление с названием задачи.

### 12.2. Регулярное событие

**Given** вокал назначен на четверг 15:00 и напоминание за 30 минут  
**When** наступает 14:30  
**Then** уведомление относится к конкретному четверговому экземпляру.

### 12.3. Snooze

**Given** показано уведомление  
**When** пользователь выбирает «Отложить»  
**Then** создаётся новая доставка на выбранное время  
**And** исходная доставка не повторяется.

### 12.4. Работа в трее

**Given** окно закрыто, но режим трея включён  
**When** наступает время напоминания  
**Then** уведомление доставляется без повторного открытия окна.

### 12.5. Полное завершение

**Given** Tiempio был полностью завершён во время напоминания  
**When** пользователь запускает приложение позже  
**Then** пропущенное напоминание показывается как пропущенное  
**And** приложение не утверждает, что могло доставить его во время полного
завершения.

## 13. Темы и интерфейс

### 13.1. Четыре семейства

**Given** пользователь открывает Appearance  
**When** показан список тем  
**Then** доступны Graphite Navy, Linen Blue, Pebble Steel и Fog Indigo  
**And** Graphite Navy выбрана по умолчанию при первом запуске.

### 13.2. Цветовая схема

**Given** выбрано любое семейство  
**When** пользователь переключает System, Light или Dark  
**Then** схема применяется без перезапуска  
**And** семейство не сбрасывается.

### 13.3. Системная схема

**Given** выбрана схема System  
**When** ОС меняет светлый режим на тёмный  
**Then** Tiempio обновляет схему без потери текущего экрана и формы.

### 13.4. Перезапуск

**Given** выбраны тема и схема  
**When** приложение перезапускается  
**Then** выбор восстанавливается до показа основной рабочей области.

### 13.5. Доступность

**Given** пользователь работает с клавиатурой или не различает цветовой маркер  
**When** он использует основной workflow  
**Then** навигация, создание, редактирование и смена статуса доступны без мыши  
**And** срочность имеет текстовое обозначение  
**And** видимый focus не теряется.

### 13.6. Поддерживаемые языки

**Given** пользователь открывает отдельный раздел «Язык»

**When** показан выбор языка

**Then** доступны System, Русский, English и Español

**And** для выбора языка не требуется открывать раздел «Темы».

### 13.7. Смена языка без перезапуска

**Given** открыта карточка задачи и выбраны тема и фильтры  
**When** пользователь меняет русский на испанский  
**Then** видимый интерфейс, accessibility labels и ошибки переключаются на
испанский без перезапуска  
**And** открытая карточка, тема и фильтры сохраняются  
**And** пользовательские названия и описания не изменяются.

### 13.8. Системный язык

**Given** выбран язык System  
**When** системный locale начинается с `ru` или `es`  
**Then** применяется соответственно русский или испанский  
**And** для любого другого неподдерживаемого locale применяется английский.

### 13.9. Даты, время и множественное число

**Given** одна и та же задача открывается на русском, английском и испанском  
**When** интерфейс показывает дату, относительный срок и количество задач  
**Then** формат и форма множественного числа соответствуют выбранному языку  
**And** исходная ISO-дата и первый день недели не изменяются  
**And** неделя начинается с понедельника во всех трёх языках.

### 13.10. Полнота локализации

**Given** в интерфейс добавлен новый пользовательский текст  
**When** выполняется quality gate  
**Then** сборка не проходит при строковом литерале вместо ключа  
**And** сборка не проходит, если в одном из каталогов нет ключа или параметры
перевода не совпадают.

### 13.11. Main process

**Given** пользователь сменил язык  
**When** Tiempio показывает меню, системный диалог, трей или новое уведомление  
**Then** текст использует выбранный язык  
**And** через IPC передаётся стабильный код, а не готовая англоязычная строка.

### 13.12. Иерархия поверхностей

**Given** открыта доска Today в любой теме и светлой или тёмной схеме  
**When** пользователь сравнивает колонку и лежащую на ней карточку  
**Then** подложка колонки визуально темнее и глубже карточки  
**And** граница карточки читается без наведения.

### 13.13. Liquid Glass fallback

**Given** окружение не поддерживает `backdrop-filter` или blur отключён  
**When** Tiempio показывает стеклянную поверхность  
**Then** используется непрозрачный семантический fallback  
**And** текст, focus, границы и иерархия остаются читаемыми.

### 13.14. Личная оболочка

**Given** пользователь открывает основной экран  
**When** интерфейс построен  
**Then** четыре основных раздела доступны в верхней навигации  
**And** постоянная корпоративная левая rail отсутствует  
**And** интерфейс не показывает issue keys, sprint-термины или выдуманное имя
пользователя.

### 13.15. Быстрое создание

**Given** пользователь находится в Today  
**When** он смотрит на колонку `TODO`  
**Then** доступно заметное полноширинное действие «Новая задача»  
**And** то же создание доступно через постоянную кнопку в верхней панели  
**And** оба пути открывают одну форму.

### 13.16. Фильтры

**Given** экран показывает задачи  
**When** пользователь выбирает проект или тег  
**Then** активные фильтры видны рядом с контекстом экрана  
**And** длинная испанская подпись не перекрывает кнопку создания или навигацию.

### 13.17. Точная срочность

**Given** задача относится к today, overdue, risk или future  
**When** она показана на доске  
**Then** карточка содержит точное локализованное значение срока  
**And** цвет не является единственным носителем смысла  
**And** разговорная подпись не заменяет количество дней.

### 13.18. Ширина окна

**Given** открыта доска Today  
**When** окно широкое  
**Then** видны четыре колонки в один ряд  
**When** окно имеет среднюю ширину  
**Then** колонки образуют сетку 2 × 2  
**When** окно компактное  
**Then** виден один выбранный статус и доступный с клавиатуры переключатель  
**And** пользователь не обязан прокручивать последовательность из четырёх
длинных колонок.

### 13.19. Выпадающие списки

**Given** пользователь выбирает статус, проект или фильтр

**When** он открывает список мышью или клавиатурой

**Then** Tiempio показывает собственный listbox в активной теме

**And** список не обрезается границами окна

**And** доступны стрелки, Home, End, Enter, Space, Escape и поиск по первой букве

**And** выбранный вариант и активный вариант доступны скринридеру.

### 13.20. Несохранённые изменения

**Given** пользователь изменил задачу и пытается закрыть редактор

**When** Tiempio запрашивает подтверждение

**Then** показывается локализованный модальный диалог в активной теме

**And** кнопки однозначно описывают «не сохранять» и «продолжить редактирование»

**And** безопасное продолжение редактирования получает фокус по умолчанию

**And** диалог закрывается через Escape с сохранением введённых данных.

## 14. Конфликт редактирования

### 14.1. Устаревшая карточка

**Given** карточка задачи открыта  
**And** та же задача была изменена на доске  
**When** карточка пытается сохранить старую revision  
**Then** Tiempio не перезаписывает новое состояние молча  
**And** показывает контролируемое предложение перечитать актуальную задачу.

## 15. Миграции

### 15.1. Обновление старой базы

**Given** база имеет поддерживаемую старую версию  
**When** запускается новая версия Tiempio  
**Then** перед миграцией создаётся внутренний backup  
**And** миграции применяются один раз по порядку  
**And** пользовательские данные остаются доступны.

### 15.2. Ошибка миграции

**Given** миграция завершается ошибкой  
**When** Tiempio обрабатывает сбой  
**Then** незавершённая транзакция откатывается  
**And** приложение не продолжает работу с частично изменённой схемой  
**And** пользователю предлагается безопасное восстановление.

## 16. Security acceptance

Следующие проверки являются release-gates, хотя не представлены отдельными
экранами:

- renderer не имеет `require`, `process` и произвольного `ipcRenderer`;
- входные IPC payload проходят runtime-валидацию;
- sender привилегированного IPC проверяется;
- production UI загружается через локальный custom protocol;
- CSP запрещает выполнение непредусмотренного кода;
- внешняя ссылка проходит allowlist схем и открывается только после валидации;
- путь к базе и системные stack traces не попадают в пользовательские DTO;
- packaged-приложение создаёт, открывает и резервирует SQLite-базу без внешнего
  нативного модуля.

## 17. Repository quality acceptance

### 17.1. Чистый checkout

**Given** Tiempio получен в новый рабочий каталог  
**When** выполняются `npm ci` и `npm run quality`  
**Then** форматирование, repository policy, lint, i18n audit, тесты и оба
typecheck проходят без локальных ручных настроек.

### 17.2. Окончания строк

**Given** в текстовый файл добавлен CRLF или одиночный CR  
**When** выполняется `npm run repo:audit`  
**Then** gate завершается ошибкой и называет файл  
**And** `.gitattributes` нормализует текстовые файлы в LF.

### 17.3. Кодировка и final newline

**Given** текстовый файл содержит UTF-8 BOM, невалидный UTF-8 или не имеет
завершающего LF  
**When** выполняется `npm run repo:audit`  
**Then** gate завершается ошибкой с конкретной причиной  
**And** случайный trailing whitespace также блокирует gate  
**But** Markdown hard break ровно из двух пробелов остаётся допустимым.

### 17.4. Единый стиль

**Given** исходник не соответствует общему Prettier-конфигу  
**When** выполняется `npm run format:check`  
**Then** commit блокируется  
**And** `npm run format` приводит файл к одинарным кавычкам, отсутствию точек с
запятой, ширине 100 и tabs шириной 4.

### 17.5. Pre-commit hook

**Given** разработчик создаёт commit  
**When** срабатывает repository-managed hook  
**Then** запускается полный `npm run precommit`  
**And** commit не создаётся при падении любой обязательной проверки.

### 17.6. Воспроизводимая установка

**Given** `package.json` и `package-lock.json` находятся в change set

**When** запускается `npm run deps:install-check`

**Then** во временном каталоге успешно выполняется чистый `npm ci` без lifecycle scripts

**And** рабочие `node_modules` и lockfile не изменяются

**And** несовместимые manifest и lockfile блокируют commit.

### 17.7. Граница dependency audit

**Given** запускается `npm run deps:audit`

**Then** production dependency tree содержит `0 high` и `0 critical`

**And** любой новый high или critical tooling advisory блокирует commit

**And** единственный рассмотренный development-only advisory
`GHSA-mh99-v99m-4gvg` отслеживается явно, а не скрывается общим исключением.
